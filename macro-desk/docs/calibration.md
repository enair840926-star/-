# 주간 보정

`data/history/predictions.jsonl`에 쌓인 실측으로 파라미터를 근거 기반으로 갱신한다.
**중립밴드만 자동 적용하고, 나머지는 리포트로 제안한다.**

구현 `src/engine/calibrate.ts` · CLI `scripts/calibrate.ts` · 테스트 31개

---

## 0. 원칙

**계산은 결정적 스크립트가 한다.** 같은 기록이면 같은 제안이 나온다.
예약 루틴은 스크립트를 실행하고 결과를 전달만 하며, "이번엔 이 정도로 조정하자" 같은
판단을 하지 않는다.

**자기참조를 관리한다.**

| 대상 | 입력 | 자기참조? | 처리 |
|---|---|---|---|
| 중립밴드 | 실현 변화율 | **아니오** — 시장이 얼마나 움직였는지는 우리 예측과 무관 | 전 버전 기록 사용 |
| 확신도·게이트·위치배수 | 우리 예측 vs 적중 | 예 | 현재 ruleset 기록만 |
| 팩터 가중치·블록 상한 | 팩터 기여 vs 적중 | 예 + 도메인 판단 | 현재 ruleset 기록만 · 승인 필수 |

파라미터를 바꾸면 그 이전 데이터는 다른 모집단이 된다. 그래서 B·C 등급 집계는
기본적으로 `RULESET_VERSION`과 같은 버전의 기록만 쓴다(`--all`로 전체 조회 가능).

**파라미터는 코드가 아니라 데이터다.** 스크립트가 `weights.ts`를 자동으로 고치지 않는다.
조정 대상만 `src/engine/params.json`에 두고 스크립트는 그 JSON만 갱신한다.

```jsonc
{ "version": 1, "updatedAt": "...", "source": "calibrated:2026-08-16",
  "neutralBandPct": { "NAS100": 0.35, "XAUUSD": 0.35, "USOIL": 0.8, "EURUSD": 0.2 } }
```

## A등급 — 중립밴드 (자동 적용)

"8시간 동안 이 자산이 보통 얼마나 움직이나". 채점 완료 기록의 `|movePct|` 분포를 쓴다.

### 왜 p30인가

중립밴드는 "이 이상 움직여야 방향이 있었다고 인정"하는 선이다.

- 너무 낮으면 노이즈를 방향으로 인정 → 적중률이 동전던지기에 수렴
- 너무 높으면 대부분 `realized = 0` → **방향을 맞춰도 miss로 채점**

중앙값으로 잡으면 세션 절반이 중립이 되어 완벽한 예측의 적중률 상한이 50%다.
동전던지기와 구분이 안 된다. **p30이면 세션의 70%가 방향 있음으로 채점되고 상한이 70%가 된다.**

### 안전장치

| 항목 | 값 |
|---|---|
| 최소 표본 | 자산당 20건 |
| 1회 변화 한도 | ±30% (초과분은 클램프하고 원값을 리포트에 병기) |
| 절대 범위 | 0.05% ~ 3.0% |
| 반올림 | 소수 둘째 자리 |

자동 적용됐더라도 **이전값 → 새값**을 리포트와 알림에 반드시 남긴다.

## B등급 — 확신도 · 게이트 · 위치 배수 (제안)

**확신도 단조성** — 25-39 / 40-54 / 55-69 / 70+ 구간의 적중률이 증가해야 한다.
표본 10건 이상인 구간이 2개 이상일 때만 판정하며, 역전되면 확신도 공식이 틀린 것이다.

**방향 게이트 (현재 25)** — 중립 예측 중 실제로 움직인 비율.
표본 20건 이상에서 65% 이상이면 하향, 35% 이하면 상향을 제안한다.

**위치 배수 (확인 ×1.15 / 반증 ×0.7)** — 관계별 적중률을 비교한다.
확인이 반증보다 못 맞으면 배수를 1.0으로 되돌리라고 제안한다. 각 10건 이상 필요.

## C등급 — 팩터 가중치 · 블록 상한 (승인 필수)

기록의 `factors[]`에서 팩터별 기여 부호를 꺼내 실현 방향과 대조한다.
실현 방향이 없던(`realized = 0`) 세션과 `stance = 0`인 팩터는 제외한다.

표본이 작으므로 **Wilson 신뢰구간(95%)** 을 함께 낸다. 점추정만 보면 노이즈를 실력으로 착각한다.

- 하한 > 50% → 상향 검토
- 상한 < 50% → 하향 검토
- 그 외 → 유지
- 최소 표본 팩터당 30건

가중치는 합이 1.0이어야 하므로 한 팩터만 바꿀 수 없다. **재배분안으로만 제시하고
자동 적용하지 않는다.**

블록 상한은 `blockCapped` 여부로 나눠 적중률을 비교한다(양쪽 10건 이상).

## 실행

```bash
npm run calibrate            # 리포트 생성 + A등급 자동 적용
npm run calibrate -- --dry   # 계산·출력만, 파일 수정 없음
npm run calibrate -- --all   # ruleset 버전 무관하게 전체 집계
```

리포트는 `docs/calibration/YYYY-MM-DD.md`에 주차별로 누적된다. 삭제하지 않는다.

**주간 루틴**: 일요일 10:00 KST. 스크립트 실행 → `params.json`·리포트 커밋 → main 푸시 →
바뀐 값과 승인 대기 항목을 푸시 알림으로 전송.

## 예상 일정

| 시점 | 상태 |
|---|---|
| 1주차 | 전 항목 "표본 부족". 리포트만 생성된다 |
| 2주차 | 자산당 20건 도달 → 중립밴드 자동 보정 시작 |
| 3~4주차 | 확신도 구간 단조성 판정 가능 |
| 6주차 이후 | 팩터 표본 30건 도달 → 가중치 재배분안 |

첫 2주는 리포트가 거의 비어 있다. 그게 정상이다.

## 승인 절차

B·C 등급 제안을 받아들이려면:

1. 리포트에서 표본 수와 Wilson 하한을 확인한다 — 점추정만 보고 바꾸지 않는다
2. 바꿀 값을 정한다(가중치는 합 1.0 유지)
3. `src/engine/weights.ts`를 수정하고 `RULESET_VERSION`을 올린다
4. 그 시점부터 B·C 집계의 모집단이 새로 시작된다

`RULESET_VERSION`을 올리지 않으면 다른 규칙으로 낸 예측이 한 모집단에 섞인다.
