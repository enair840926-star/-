# Fusion Ruleset v1.1

당일 방향성을 **매크로·위치·이벤트** 레이어로 나눠 각각 독립 계산한 뒤,
융합 레이어가 그 값을 읽기만 해서 방향·확신도·근거 문장을 만든다.

`RULESET_VERSION = fusion-v1.1` · 구현 `src/engine/` · 테스트 `src/engine/__tests__/` (138개)

| 모드 | 입력 | 용도 |
|---|---|---|
| `macro-only` (기본) | 외부요인 + 관측 레벨 | 폰만 있을 때 받아보는 당일 방향성 |
| `fusion` | 외부요인 + v4 통합 번들 캔들 | 번들을 붙일 수 있을 때의 정밀 판단 |

---

## 0. 설계 원칙

1. **레이어 잠금** — 어떤 레이어도 다른 레이어의 값을 고쳐 쓰지 않는다. 융합은 원값을
   그대로 보존해 출력한다. **방향은 매크로가 정하고**, 가격·이벤트는 확신도와 문장만 바꾼다.
2. **결정적 계산** — 같은 입력이면 항상 같은 출력. 수치형 팩터는 사람이 부호를 고르지 않는다.
3. **모르면 비운다** — 확인 못 한 근거는 채우지 않는다. 커버리지가 떨어지고 확신도가 자동으로 깎인다.
4. **변화·서프라이즈만 본다** — 수준(level)은 방향 근거가 아니다.
5. **방향은 분석 좌표** — 주문 실행·포지션 크기·레버리지 결정을 대신하지 않는다.

## 1. 매크로 레이어

### 1.1 stance의 정의

stance는 언제나 **직전 세션 대비 변화 또는 컨센서스 대비 서프라이즈**이며, 부호는
"이 자산 가격에 대한 압력"으로 맞춘다.

- ✗ "DXY 99.91, 5주 고점권" → 강세니까 음수  ← 수준으로 읽으면 세션마다 부호가 뒤집힌다
- ○ "DXY 99.91, 일간 −0.05%" → 변화 −0.05% → 밴드상 0

### 1.2 입력

```jsonc
// 수치형 — value만 넣는다. stance는 엔진이 밴드에서 파생한다.
{ "key": "usRates", "value": 7.5, "confidence": 0.9, "fact": "yields",
  "note": "미 10Y 4.745%, 전일 +7.5bp", "source": "FXStreet", "asof": "2026-07-31T20:00:00Z" }

// 서수형 — 앵커 문구에 대응시켜 stance를 넣는다.
{ "key": "safeHaven", "stance": 2, "confidence": 0.8, "fact": "hormuz",
  "note": "호르무즈 유조선 회항", "source": "Bloomberg", "asof": "2026-07-31T20:00:00Z" }
```

- `confidence` 0~1 (생략 시 0.7) — 출처 신뢰도
- `fact` — **동일한 사건·발표 한 건**의 식별자. 테마가 아니다
- `asof` — 근거를 확인한 시각. 감쇠 기준
- 수치형에 `value` 없이 `stance`만 주면 계산은 하되 `STANCE_UNVERIFIED`, 신뢰도 0.5 제한
- 필수 입력이 없으면 그 팩터는 버리고 `MISSING_VALUE` / `MISSING_STANCE`

### 1.4 공통 앵커

**연준 스탠스** (`fedPolicy`, 전 자산 동일 부호)

| +2 | +1 | 0 | −1 | −2 |
|---|---|---|---|---|
| 인하 시사·완화 서프라이즈 | 비둘기 우세 | 변화 없음 | 매파 발언·인상 소수의견 | 인상 시사·긴축 서프라이즈 |

**지정학·안전자산** (`safeHaven`, `geopolitics`)

| +2 | +1 | 0 | −1 | −2 |
|---|---|---|---|---|
| 무력충돌·항로 차단 등 실제 사건 | 긴장 고조 보도 | 변화 없음 | 완화·휴전 진전 | 합의 타결 |

### 1.5 계산

```
score      = Σ(w_eff · stance) / Σ(w_eff)      → -2 ~ +2
coverage   = Σ(w_eff)                          → 0 ~ 1
dispersion = 블록 점수 간 가중표준편차 / 2      → 0 ~ 1
confidence = coverage × (1 − 0.6 × dispersion)
```

`coverage < 0.5` → `MACRO_COVERAGE_LOW` · `dispersion > 0.5` → `MACRO_HIGH_DISPERSION`

## 2. 시간 감쇠

```
age        = asof ~ 스냅샷 시각의 **시장 시간**   (주말 휴장 제외)
halfLife   = persistent ? 72시간 : 18시간
w_eff 기여 = confidence × 0.5^(age / halfLife)
age > 48시간 && !persistent → 팩터 제외, FACTOR_STALE
```

- 휴장 구간(금 21:00 UTC ~ 일 21:00 UTC)은 경과로 세지 않는다. 시장이 멈춰 있는 동안
  근거가 낡았다고 볼 이유가 없다. 금요일 종가 근거를 일요일에 읽어도 시장 시간으로는 몇 시간이다.
- `persistent`는 다음 회의·발표까지 유효한 정책 스탠스에만 쓴다 (`fedPolicy`, `ecbPolicy`, `opec`).

## 3. 블록 — 한 이야기가 여러 번 세지지 않게

### 3.1 블록 구성

| 자산 | 블록 (원 가중 합) |
|---|---|
| NAS100 | rates 0.54 (usRates·fedPolicy·dollar) · tape 0.46 (riskAppetite·megacapEarnings·breadth) |
| XAUUSD | rates **0.66** (realYield·dollar·fedPolicy) · geo 0.16 · infl 0.10 · flows 0.08 |
| USOIL | supply 0.34 (supplyRisk·geopolitics) · inv 0.22 · policy 0.18 · demand 0.16 · fx 0.10 |
| EURUSD | rates 0.44 (rateDiff·fedPolicy) · ecb 0.18 · usdata 0.14 · ezdata 0.14 · tape 0.10 |

### 3.2 규칙 A — 사실 중복 감쇠

같은 블록에서 같은 `fact`를 인용한 팩터가 둘 이상이면, 가중치가 가장 큰 하나만 100%,
나머지는 **40%** 로 줄인다.

- ○ 호르무즈 유조선 회항 → `supplyRisk`와 `geopolitics`가 `fact: "hormuz"` 공유
- ✗ "주식이 강했다" 같은 테마로 묶기 — 서로 다른 관측치는 블록이 이미 처리한다

### 3.3 규칙 B — 블록 상한 0.6

한 블록의 유효 가중치가 전체의 60%를 넘으면 **그 블록만** 60% 비중으로 줄인다.
나머지 블록을 끌어올려 총합을 보존하지 않는다 — 근거가 한쪽에 몰려 있으면 실제로
커버리지가 낮은 것이므로, 총합이 줄어 확신도가 함께 낮아지는 것이 맞다.

블록 간 상대 가중치는 어느 방식이든 같으므로 **점수는 바뀌지 않고 확신도만 낮아진다.**

### 3.4 규칙 C — 분산은 블록 단위로

`dispersion`을 팩터 단위가 아니라 블록 점수 간으로 계산한다. 같은 진영 안의 미세한
이견을 "시장이 갈렸다"로 오독하지 않는다.

## 4. 위치 레이어 (macro-only)

번들 없이 얻는 가격 정보를 확인·반증 신호로 쓴다. **방향은 바꾸지 않는다.**

### 4.1 입력

```jsonc
"levels": { "last": 84.67, "prevClose": 83.59, "support": [82.5], "resistance": [85],
            "note": "...", "source": "..." }
```

`last`는 필수(예측 기준가로도 쓰인다). `prevClose`가 없으면 위치 레이어만 비활성(`POSITION_UNAVAILABLE`).
지지·저항은 **기사에 인용된 값만** 넣는다.

### 4.2 계산

```
pos = tanh(전일 종가 대비 변화율 / 자산별 중립밴드)
      + 0.3 (최근접 저항 상향 돌파)  − 0.3 (최근접 지지 이탈)
    → [-1, +1]
```

| 관계 | 조건 | 확신도 배수 |
|---|---|---|
| 확인 | \|pos\| ≥ 0.3, 매크로와 같은 부호 | ×1.15 |
| 반증 | \|pos\| ≥ 0.3, 반대 부호 | ×0.70 |
| 중립 | \|pos\| < 0.3 또는 \|매크로 점수\| < 0.35 | ×1.00 |
| 미수집 | prevClose 없음 | ×1.00 |

## 6. 판정

### 6.1 macro-only

```
score      = 매크로 점수
확신도     = 100 × min(1, |score|/1.5) × (0.5 + 0.5×매크로컨피던스) × 0.9 × 위치배수
             → 상한 70 → 이벤트 상한 → 블랙아웃이면 30 이하
방향 게이트 = 25
```

레짐은 매크로 내부 일치도로 판정한다.

| 상태 | 조건 | 표기 |
|---|---|---|
| ALIGNED | \|score\| ≥ 0.5, 분산 ≤ 0.5 | 요인 일치 |
| PARTIAL | \|score\| ≥ 0.5, 분산 > 0.5 | 우세·일부 상충 |
| CONFLICT | \|score\| < 0.5, 분산 > 0.5 | 요인 상충 |
| RANGE | \|score\| < 0.5, 분산 ≤ 0.5 | 요인 중립 |

### 6.2 fusion

차트 레이어(D1 0.30 / H4 0.30 / H1 0.22 / M15 0.18, 추세·구조·모멘텀)를 계산해
합의 매트릭스(동조 ×1.15 / 부분동조 ×0.9 / 상충 ×0.5 / 양측중립 ×0.6)로 합친다.
레이어 가중은 이벤트 최고 티어에 따라 차트 0.60~0.50, 매크로 0.40~0.50. 방향 게이트 35.

### 6.3 공통

| 확신도 | 라벨 |
|---|---|
| 65 이상 | 높음 |
| 40 ~ 64 | 중간 |
| 40 미만 | 낮음 |

방향 이산화: `≥1.0 → +2`, `≥0.35 → +1`, `≤−1.0 → −2`, `≤−0.35 → −1`, 나머지 0.
`validUntil = min(현재 +8시간, 다음 세션 경계, 다음 블랙아웃 시작)`

## 7. 검증 루프

**평가 구간은 다음 스냅샷까지(8시간)로 고정한다.** 자산별로 다르게 두지 않는다.

### 7.1 중립 밴드 (8시간 기준 초기값)

| NAS100 | XAUUSD | USOIL | EURUSD |
|---|---|---|---|
| 0.35% | 0.35% | 0.80% | 0.20% |

30건 이상 쌓이면 실제 분포로 재보정한다.

### 7.2 기록과 채점

`data/history/predictions.jsonl`에 스냅샷마다 자산별 1줄을 남긴다.

| 필드 | 나중에 무엇을 보정하는가 |
|---|---|
| `direction`·`score`·`refPrice` | 중립밴드, 방향 게이트 |
| `conviction` | 확신도 공식 |
| `coverage`·`dispersion` | 확신도 공식의 커버리지·분산 계수 |
| `factors[]` (key·stance·최종 가중치) | **팩터 가중치 표와 블록 상한** |
| `positionRelation` | 위치 배수(×1.15 / ×0.7)가 실제로 도움이 되는지 |
| `eventTier` | 이벤트 확신도 상한이 적정한지 |

팩터 기여 내역이 없으면 가중치는 영원히 보정할 수 없다. 기록 시점에 함께 남겨야 한다.

다음 실행에서 `horizonEnd`가 지난 기록을 그 시점 가격으로 채점한다.

```
movePct  = (endPrice − refPrice) / refPrice × 100
realized = movePct > 밴드 ? +1 : movePct < −밴드 ? −1 : 0
hit      = direction ≠ 0 && sign(direction) === realized
```

- 20시간을 넘겨도 채우지 못하면 실행 누락으로 닫는다.
- `direction === 0`은 적중률 모수에서 빼되, 실제로 움직였는지를 따로 센다
  → **"중립이라 했는데 움직였다"** 비율이 과보수성 지표다.

### 7.3 스코어보드

`macro.json`의 `scoreboard`에 자산별·확신도 구간별(25-39 / 40-54 / 55-69 / 70+) 적중률이 담긴다.
**확신도 구간별 적중률이 단조증가하지 않으면 확신도 공식이 틀린 것이다.** 이것이 v1.2의 근거가 된다.

## 8. 금지 사항

- 수준(level)을 근거로 stance 부호를 정하기 — 변화·서프라이즈만 본다
- 확인 못 한 팩터를 지어내 커버리지 경고를 감추기
- 같은 사실을 여러 팩터에 나눠 넣어 가중치를 부풀리기 (`fact`를 공유해야 한다)
- 가격이나 이벤트로 방향 자체를 뒤집기 — 둘 다 확신도만 조정한다
- macro-only에서 무효화 "가격"을 계산해 제시하기 (관측 레벨만 인용한다)
- 확신도를 근거로 주문 크기·레버리지를 산출하기

## 9. v1.0 → v1.1 변경 요약

| 문제 | 해결 |
|---|---|
| 같은 사실이 세션마다 반대 부호로 입력됨 (7/29 DXY 음수 ↔ 8/2 DXY 양수) | stance를 변화 기준으로 고정 + 수치형은 밴드에서 파생 |
| 골드 금리 복합체가 가중치의 66% — 금리 한 건이 방향을 결정 | 블록 상한 0.6 + `fact` 중복 감쇠 |
| 상충 페널티가 점수와 확신도에 이중 적용 | 분산을 블록 단위로 계산 |
| 신선도 감쇠가 수동 | `asof` 기준 자동 감쇠, 휴장 시간 제외 |
| 예측 검증 수단 없음 | 예측 로그 + 8시간 채점 + 스코어보드 |
| 가격 정보가 판단에 미반영 | 위치 레이어(확신도만 조정) |
