# Fusion Ruleset v1.1 — 초안

v1.0의 분석 로직 결함 5건을 고친다. 구현 전 확정용 문서이며, 확정 후
`fusion-ruleset-v1.md`에 병합하고 `RULESET_VERSION`을 `fusion-v1.1`로 올린다.

## 고치는 것

| # | 문제 | 해결 |
|---|---|---|
| 1 | stance가 "수준"인지 "변화"인지 정의 없음 → 같은 사실이 세션마다 반대 부호 | 팩터별 수치→stance 변환표. 수치형은 stance를 **입력받지 않고 파생** |
| 2 | 한 사실이 여러 팩터에 중복 반영 (골드 금리 복합체 66%) | 블록 상한 + `fact` 중복 감쇠 |
| 3 | 상충 페널티 이중 적용 | 분산을 블록 단위로 계산 (팩터 단위 과대평가 제거) |
| 4 | 시간 감쇠가 수동 | `asof` 기준 자동 반감기 |
| 5 | 검증 루프 없음 · 예측 구간 미정의 | 예측 로그 + 채점 + 적중률 스코어보드 |

추가로 **위치 레이어**를 넣는다. 번들 없이도 얻는 "현재가가 전일 종가·주요 레벨 대비
어디인가"가 지금은 전혀 쓰이지 않는다.

## 1. 팩터 루브릭 (stance 고정)

### 1.1 원칙

- **stance는 언제나 변화·서프라이즈 기준이다.** 수준(level)은 `note`에만 적고 점수에 넣지 않는다.
  - ✗ "DXY 99.91, 5주 고점권" → 강세니까 음수
  - ○ "DXY 99.91, 일간 −0.05%" → 변화 −0.05% → 밴드상 0
- **수치형 팩터는 `value`(지표 실측치)를 입력하고 stance는 엔진이 밴드에서 파생한다.**
  사람(또는 LLM)이 부호를 고르지 않으므로 재현된다.
- **서수형 팩터는 `stance`를 입력하되 앵커 문구 중 하나에 대응시킨다.**
- 지표를 확인 못 하면 그 팩터를 **넣지 않는다**. 커버리지가 떨어지고 확신도가 자동으로 깎인다.

입력 스키마:

```jsonc
// 수치형 — stance 없음
{ "key": "usRates", "value": 7.5, "note": "미 10Y 4.745%, 전일 +7.5bp", "source": "CNBC", "asof": "2026-07-31T20:00:00Z" }
// 서수형 — stance 필수
{ "key": "safeHaven", "stance": 2, "note": "호르무즈 유조선 회항", "fact": "hormuz", "source": "Bloomberg" }
```

수치형에 `stance`만 주면 계산은 하되 `STANCE_UNVERIFIED` 플래그를 남기고 confidence를 0.5로 제한한다(v1.0 입력 하위호환).

## 2. 시간 감쇠

```
age        = 스냅샷 generatedAt − factor.asof            (시간)
halfLife   = factor.persistent ? 72 : 18                 (시간)
c_eff      = confidence × 0.5^(age / halfLife)
age > 48h  && !persistent  → 팩터 제외, FACTOR_STALE 플래그
```

- `asof` 생략 시 age = 0 (이번 세션에 새로 확인한 값으로 본다).
- `persistent: true`는 **다음 회의·다음 발표까지 유효한 정책 스탠스**에만 쓴다
  (`fedPolicy`, `ecbPolicy`, `opec`). 시장 가격·지표 변화에는 쓰지 않는다.

효과: 08:00에 수집한 금요일 근거가 22:00 스냅샷에서 약 56%(14시간 경과) 가중으로 줄어든다.

### 3.2 규칙 A — 블록 상한 0.6

한 블록의 유효 가중치(Σ w·c_eff)가 전체의 60%를 넘으면 그 블록을 60%로 정규화하고
나머지 블록을 비례 확대한다. **한 갈래의 이야기가 결과를 지배하지 못하게 한다.**
주도 요인의 힘은 인정하되 단독 지배만 막는 수준이다.

### 3.3 규칙 B — 사실 중복 감쇠

팩터에 선택적 `fact` 식별자를 붙인다(예: `"fact": "hormuz"`).
**같은 블록에서 같은 `fact`를 공유하는 팩터가 둘 이상이면, 가중치가 가장 큰 하나만 100%,
나머지는 40%로 감쇠**한다. 한 뉴스가 두 번 세 번 세지는 것을 막는다.

`fact`는 **동일한 사건·발표 한 건**을 뜻한다. 테마가 아니다.
- ○ 호르무즈 유조선 회항 → `supplyRisk`와 `geopolitics`가 `fact: "hormuz"` 공유
- ✗ "주식이 강했다" 같은 테마로 `riskAppetite`와 `breadth`를 묶기 (서로 다른 관측치다 — 블록이 이미 처리한다)

### 3.4 규칙 C — 분산을 블록 단위로

`dispersion`을 팩터 6개가 아니라 **블록 점수 간** 가중표준편차로 계산한다.
같은 진영 안의 미세한 이견을 "시장이 갈렸다"로 오독하지 않는다.

블록 상한 0.6, 사실 중복 감쇠 0.4 적용. (아직 §1 루브릭은 미적용 — stance는 기존 수집값 그대로)

## 4. 위치 레이어 (macro-only 전용)

`levels`를 장식이 아니라 **확인/반증 신호**로 쓴다. 단, **방향은 매크로가 정하고
위치는 확신도와 문장만 바꾼다** — 레이어 잠금 원칙을 유지한다.

### 4.1 입력 (macro-only에서 필수)

```jsonc
"levels": {
  "last": 84.67,          // 필수 — 리서치 시점 가격
  "prevClose": 83.6,      // 필수 — 직전 세션 종가
  "support": [82.5],      // 선택 — 기사에 인용된 값만
  "resistance": [85.0],
  "note": "...", "source": "..."
}
```

### 4.2 계산

```
move = (last − prevClose) / prevClose
pos  = tanh(move / 중립밴드)                       → −1 ~ +1
레벨 보정: last > 최근접 저항 → +0.3
           last < 최근접 지지 → −0.3
pos  = clamp(pos, −1, +1)
```

### 4.3 확신도 반영 (방향은 바꾸지 않는다)

| 관계 | 조건 | 배수 |
|---|---|---|
| 확인 | \|pos\| ≥ 0.3, 부호 일치 | ×1.15 |
| 반증 | \|pos\| ≥ 0.3, 부호 반대 | ×0.70 |
| 중립 | \|pos\| < 0.3 | ×1.00 |
| 미수집 | prevClose 없음 | ×1.00 + `POSITION_UNAVAILABLE` |

플레이북에 한 줄 추가:
`… · 가격도 확인(전일 종가 +1.3%)` 또는 `… · 가격은 반대(지지 이탈)`

## 5. 검증 루프

### 5.1 예측 구간 정의

**다음 스냅샷까지(8시간)** 를 평가 구간으로 한다. 08:00 예측은 16:00 가격으로,
16:00 예측은 22:00 가격으로 채점한다. 자산별로 다르게 두지 않는다(단순·일관).

### 5.2 중립 밴드 (8시간 기준 초기값)

| 자산 | 밴드 | 근거 |
|---|---|---|
| NAS100 | 0.35% | 8시간 평균 실현 변동의 대략적 절반 수준 |
| XAUUSD | 0.35% | 〃 |
| USOIL | 0.80% | 변동성이 가장 큼 |
| EURUSD | 0.20% | 가장 작음 |

**초기 추정치다.** 30건 이상 쌓이면 실제 분포로 재보정한다.

### 5.3 기록 — `data/history/predictions.jsonl` (append-only)

```jsonc
{"ts":"2026-08-03T23:00:00Z","ruleset":"fusion-v1.1","asset":"USOIL","mode":"macro-only",
 "direction":1,"conviction":29,"score":0.712,"regime":"PARTIAL",
 "refPrice":84.67,"horizonEnd":"2026-08-04T07:00:00Z","outcome":null}
```

### 5.4 채점 (매 실행 시, 새 스냅샷을 쓰기 전에)

`horizonEnd ≤ 현재`이고 `outcome === null`인 기록에 대해:

```
endPrice = 이번 실행의 levels.last
movePct  = (endPrice − refPrice) / refPrice × 100
realized = movePct > 밴드 ? +1 : movePct < −밴드 ? −1 : 0
hit      = direction ≠ 0 && realized === direction
```

- 경과가 20시간을 넘으면 `skipped: "stale"`로 닫는다(실행 누락 구간).
- `direction === 0`은 적중률 모수에서 제외하되, `realized ≠ 0`이었는지를 따로 센다
  → **"중립이라 했는데 실제로는 움직였다"** 비율이 과보수성 지표가 된다.

### 5.5 스코어보드 → `macro.json` + 화면 + 알림

```jsonc
"scoreboard": {
  "window": 30,
  "byAsset":      { "USOIL": { "n": 12, "hit": 7, "rate": 0.58, "neutralN": 8, "neutralMoved": 3 } },
  "byConviction": { "25-39": { "n": 20, "hit": 11, "rate": 0.55 }, "40-54": {…}, "55-70": {…} },
  "updatedAt": "…"
}
```

확신도 구간별 적중률이 단조증가하지 않으면 확신도 공식이 틀린 것이다 — 이게 v1.2의 근거가 된다.

## 6. 알림 형식 보완

v1.1은 v1.0보다 중립이 늘어난다(중복 계산 제거의 정직한 결과). 대신 **편향의 방향과 세기를

```
적중률 최근 30건 58% (확신도 40+ 구간 67%)
```

## 7. 하위호환·마이그레이션

- v1.0 입력(`value` 없이 `stance`만)은 계속 동작한다 → `STANCE_UNVERIFIED`, confidence ≤ 0.5.
- `levels.prevClose`가 없으면 위치 레이어만 비활성(`POSITION_UNAVAILABLE`).
- `public/macro.json`은 version 2를 유지하고 `scoreboard`·`position` 필드를 추가한다.
  구형 v1 필드는 그대로 두어 화면 호환을 깨지 않는다.
- `predictions.jsonl`은 새 파일이므로 기존 이력 없음. `ruleset` 필드로 버전을 구분한다.

## 8. 구현 순서

각 단계는 **테스트 통과 → 스냅샷 재생성 → 개별 커밋**으로 닫는다.

| 단계 | 내용 | 검증 |
|---|---|---|
| 1 | 팩터 루브릭·밴드표·stance 파생·입력 검증 | 밴드 경계값 테스트, 하위호환 테스트 |
| 2 | 시간 감쇠 | 반감기·48시간 컷·persistent 테스트 |
| 3 | 블록 상한·`fact` 중복 감쇠·블록 분산 | 오늘 데이터로 §3.5 수치 재현 |
| 4 | 위치 레이어 | 확인/반증/미수집 3경로 테스트 |
| 5 | 예측 로그·채점·스코어보드·UI·알림 | 인공 로그로 채점 로직 테스트 |

1~4는 계산 결과가 바뀌므로 끝난 뒤 latest.json을 새 스키마로 다시 채워야 한다
(오늘 수집분은 `value`가 없어 대부분 `STANCE_UNVERIFIED`가 된다 → 재수집 1회 필요).
